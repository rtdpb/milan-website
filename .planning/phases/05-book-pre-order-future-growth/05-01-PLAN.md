## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| visitor browser → Web3Forms API | BookInterestForm submits name+email to api.web3forms.com (untrusted user input leaves the page). |
| visitor browser → Substack | Primary capture redirects to an external Substack URL (only when the config sentinel is replaced). |
| build config → rendered HTML | `TODO_BOOK_CHECKOUT_URL` / `TODO_SUBSTACK_URL` sentinels decide whether any external URL is emitted. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01 | Tampering (DOM XSS) | BookInterestForm submit island | medium | mitigate | Only static `t.boek.*` strings written to the DOM via `textContent`; API response (`json.message`) is never echoed. Mirrors ContactForm (05-RESEARCH §Security). Verified by negative grep in Task 2. |
| T-05-02 | Spoofing (spam/abuse) | BookInterestForm | low | mitigate | Web3Forms `botcheck` honeypot checkbox (display:none, tabindex=-1). Same posture as the existing contact form. No new secret exposed — the Web3Forms access key is a public client identifier. |
| T-05-03 | Elevation (open redirect) | Checkout seam (TODO_BOOK_CHECKOUT_URL) | low | mitigate | URL is only ever the config constant, never user-supplied; block is OMITTED while the sentinel is unreplaced (IS_SENTINEL pattern), so no arbitrary href can be navigated. |
| T-05-04 | Spoofing (redirect target) | Substack subscribe anchor | low | mitigate | `subscribeUrl` derived solely from `TODO_SUBSTACK_URL`; anchor carries `rel="noopener noreferrer"` on `target="_blank"` (tab-napping). |

No high-severity threat is introduced by this plan. The book page adds no auth/session/payment surface; the only new input surface (BookInterestForm) reuses the already-hardened contact-form posture.
</threat_model>
