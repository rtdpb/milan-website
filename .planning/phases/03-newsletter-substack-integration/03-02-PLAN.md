<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| On-site signup → Substack subscribe page | New-tab redirect to external hosted opt-in |
| RSS feed → /nieuwsbrief archive render | Untrusted third-party XML content (build-time) |
| Substack post / publication anchors → user browser | External navigation (new tab) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-3-01 | Spoofing | Signup redirect anchor + archive "Lees verder" / "Alle artikelen" (`target="_blank"`) | low | mitigate | `rel="noopener noreferrer"` on every external `target="_blank"` anchor (tab-napping). Enforced via grep in acceptance criteria. |
| T-3-02 | Tampering | RSS content rendered in /nieuwsbrief archive cards | medium | mitigate | Reuse rss.ts (Plan 01): excerpt is `description` stripped to text, never `set:html`; `content:encoded` only for word-count. No RSS HTML rendered on the page. |
| T-3-06 | Tampering | Open redirect via email field on signup | low | mitigate | Redirect URL is `${TODO_SUBSTACK_URL}/subscribe` hardcoded from static config; the email is NOT appended (no `?email=` prefill) so there is no user-controlled URL construction. |
| T-3-03 | Elevation of Privilege | Build-time archive `fetch()` (SSRF) | low | mitigate | Feed URL derived solely from TODO_SUBSTACK_URL (static config); sentinel guard prevents any fetch while placeholder; never user input. |
| T-3-04 | Denial of Service | Archive feed failure during build | low | mitigate | rss.ts try/catch + res.ok → [] → placeholder fallback (D-06); build never fails. |
</threat_model>
