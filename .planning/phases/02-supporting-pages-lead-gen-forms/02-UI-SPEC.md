### 60 / 30 / 10 Split

- **60% dominant** — `#FAF8F4`: page backgrounds, hero areas, form section, footer.
- **30% secondary** — `#F0EDE7` (cards) + `#111110` (dark bands). The /mijn-verhaal page uses one designated dark band at the opening; other sections are light. Coaching and Spreker pages use the same one-dark-band structure as the homepage (one anchoring dark feature band — e.g. approach/offer section or testimonial callout — surrounded by light sections).
- **10% accent** — `#FFDD11` strictly reserved, see list below.

### Accent `#FFDD11` reserved for (explicit list — never general UI)

1. **Primary CTA button** — background on "Verstuur bericht", "Boek lezing" CTA, "Plan kennismaking" CTA, and each page's hero primary CTA. Text on yellow button: `--color-text` (#1A1A18) near-black.
2. **Active / current nav underline** — 2px yellow underline on the nav item matching the current page (baked in at build time via Astro SSG per Pattern 5 in RESEARCH.md).
3. **One eyebrow accent per dark-band section** — 4px left-border on the section eyebrow label when inside a `variant="dark"` SectionWrapper. Same pattern as Story.astro. One usage per dark section, never in light sections.
4. **Keyboard focus ring** — `outline: 2px solid var(--color-accent)` on all interactive elements (including form inputs on focus). Already defined globally.
5. **Form input focus border** — `border-color: var(--color-accent)` on `<input>` and `<select>` and `<textarea>` when focused. This replaces the default `--color-border` on focus.

Yellow is NOT used for: form backgrounds, error states (use `--color-destructive`), success states (use neutral text), card backgrounds, body text, dividers, or any decorative element beyond the 5 usages above.

### Dark band usage rule (Phase 1 D-01 carried forward)

Each new page may use **at most one** full-width dark band (`SectionWrapper variant="dark"`). Testimonials on subpages use a single dark-surface card (`Card variant="dark"`) within a light section — not a full dark band. The /mijn-verhaal page uses a dark opening band (echoing Story.astro) as its designated feature; remaining sections are light.

### ContactForm.astro — Full State Machine

The form has 7 distinct states. All are specified below. States are managed by the JS island within the `<script>` tag; the no-JS path (native POST) only renders the default HTML state.

#### State 1: Default (page load, no JS yet / no interaction)

- Form is visible. All fields empty.
- Onderwerp `<select>`: default selected option is "Algemeen" (value `algemeen`).
- Submit button: active, text = "Verstuur bericht", `background: #FFDD11`, `color: #1A1A18`.
- Result div: `hidden` attribute present — not visible.
- Visual: cream/off-white page, form fields with `--color-border` border, standard body font.

#### State 2: Placeholder key (documented non-functional state)

When `TODO_WEB3FORMS_ACCESS_KEY` is the placeholder string (production until real key is supplied):

- The form renders identically to the Default state — no visual difference for the user.
- The form is NOT faked to show success. It submits to Web3Forms, which will reject or ignore the invalid key.
- A `<!-- TODO: Replace TODO_WEB3FORMS_ACCESS_KEY in src/config.ts -->` comment is present in the HTML source.
- A `console.warn('[ContactForm] Web3Forms access key is a placeholder — form will not deliver email. Replace TODO_WEB3FORMS_ACCESS_KEY in src/config.ts.')` is emitted in the browser console when JS runs and detects the placeholder key value.
- The result area must never show a success message when the key is invalid. The API error path (State 7) handles this correctly.

#### State 3: Query-param pre-selection (on DOMContentLoaded)

- JS reads `window.location.search` for `?type=lezing|coaching|algemeen`.
- Sets `<select name="onderwerp">` `.value` to match the param value if it exists as an option.
  - `?type=lezing` → selects "Boek lezing" option (value `lezing`)
  - `?type=coaching` → selects "Plan kennismaking" option (value `coaching`)
  - `?type=algemeen` or no param → remains "Algemeen" (default)
- Only valid option values are accepted (`CSS.escape` safety check before setting `.value`).
- No visual flash — the select value is set synchronously on DOMContentLoaded before the first paint where possible.
- The Onderwerp field appears pre-selected to the user with no animation.

#### State 4: Focus / Filling

For all inputs (`<input>`, `<select>`, `<textarea>`) on focus:
- `border-color: var(--color-accent)` (#FFDD11) replaces `--color-border`.
- `outline: 2px solid var(--color-accent); outline-offset: 2px` — focus ring (doubles as brand colour, globally defined).
- Input text: `--color-text` (#1A1A18) at `--text-base` size.
- Placeholder text (before user input): `--color-text-secondary` (#5A5A52).
- Label stays above input — labels are always visible (never placeholder-only).

Form field layout:
- Each field is a `.form-group` `<div>` with `margin-bottom: var(--space-lg)` (24px).
- Label: `font-size: var(--text-xs)`, `font-weight: 600`, `color: var(--color-text)`, `display: block`, `margin-bottom: var(--space-sm)` (8px).
- Input / Select / Textarea: `width: 100%`, `height: 48px` (inputs and select), `min-height: 120px` (textarea), `padding: 0 var(--space-md)`, `border: 1.5px solid var(--color-border)`, `border-radius: var(--radius-md)` (8px), `font-size: var(--text-base)`, `font-family: var(--font-body)`, `background: var(--color-bg)`, `color: var(--color-text)`.
- Textarea: `padding: var(--space-sm) var(--space-md)`, `resize: vertical`.

Required field indicator: `<span aria-hidden="true">*</span>` after label text for Naam, Mailadres, Bericht. Not on Onderwerp (always has a default value, effectively always "filled").

#### State 5: Submitting

Triggered when the user clicks "Verstuur bericht" and the fetch is in-flight.

- Submit button: `disabled={true}`, text changes to "Versturen…", background stays `#FFDD11` but opacity drops to 0.7.
- No spinner required — text label change is sufficient for a personal-brand site.
- Form fields remain visible and readable but are NOT additionally disabled (user cannot re-submit because the button is disabled).
- Result div: still `hidden` — no message yet.
- Transition: button text changes instantly (no animation).

#### State 6: Success (after successful Web3Forms response `{ success: true }`)

- Form: `hidden` attribute added — entire form is hidden (`form.hidden = true`).
- Result div: `hidden` attribute removed — becomes visible.
- Content of result div:

```html
<p class="form-success">Bedankt! Ik neem snel contact met je op.</p>
```

- `.form-success` styling: `font-size: var(--text-lg)` (18–22px), `font-weight: 400`, `color: var(--color-text)`, `line-height: 1.5`. No icon, no additional decoration. Simple, human, honest.
- `aria-live="polite"` on the result div ensures screen readers announce the message when it appears.
- No countdown, no redirect, no animation — the message appears immediately in place of the form.
- The success copy is a static string from `nl.contact.successMsg` — never echoed from the API response body (XSS prevention per RESEARCH.md §Security Domain).

#### State 7: Error (API error `{ success: false }` or network failure)

Two error subtypes:

**API error** (Web3Forms returns `{ success: false }` — e.g. invalid key, rate limit):
- Form remains visible (form is NOT hidden).
- Result div: `hidden` removed — becomes visible.
- Content:

```html
<p class="form-error">Er is iets misgegaan. Probeer het opnieuw of mail me direct.</p>
```

- Submit button: re-enabled, text returns to "Verstuur bericht".

**Network error** (fetch throws — no internet connection):
- Same as API error pattern but different copy:

```html
<p class="form-error">Geen verbinding. Controleer je internetverbinding en probeer opnieuw.</p>
```

- Submit button: re-enabled.

`.form-error` styling: `font-size: var(--text-base)`, `font-weight: 400`, `color: var(--color-destructive)` (#C0392B), `line-height: 1.5`. No icon. Inline within the result div.

Error copy is a static string from `nl.contact.errorMsg` / `nl.contact.errorNetwork` — never echoed from user input or API response.

The result div stays visible until the user retries (clicking submit again). On retry, the result div is cleared (set back to `hidden`) and the submit cycle starts fresh.

### No-JS Fallback

Without JavaScript, the form submits via native browser POST to `https://api.web3forms.com/submit`. Web3Forms handles the submission and redirects to its default success page (or to a `redirect` field value if supplied). The form HTML is fully valid for this path — all field `name` attributes are correct, `method="POST"` is set on the `<form>`. This satisfies D-04 (no-JS fallback).

## Accessibility Contract

Inherited requirements (FND-06) carried forward to all new pages:

- Semantic landmark per page: `<header>`, `<main id="main-content">`, `<footer>`, `<nav>`, `<section aria-labelledby>`.
- Each section has a unique `id` on its heading, referenced by `aria-labelledby` on the `SectionWrapper`.
- Skip-to-content link: inherited from BaseLayout.astro.
- All images on new pages have meaningful `alt` text (see Image Pipeline Contract).
- Color contrast on new pages: `--color-text` on `--color-bg` → ~18:1 (AAA). Form labels and field text at same contrast.
- Focus ring: `outline: 2px solid var(--color-accent); outline-offset: 2px` on all interactive form elements (globally applied by Button.astro and form input focus styles).
- Form-specific accessibility:
  - Every `<input>`, `<select>`, `<textarea>` has an explicit `<label>` with `for` attribute matching the field `id`.
  - Labels are always visible — never hidden, never placeholder-only.
  - `required` attribute on required fields + `aria-required="true"` for AT redundancy.
  - `autocomplete="name"` on Naam field; `autocomplete="email"` on Mailadres field.
  - Honeypot has `aria-hidden="true"` and `tabindex="-1"`.
  - `aria-live="polite"` on the result `<div>` for screen-reader announcement of success/error messages.
  - Required field asterisks marked `aria-hidden="true"` — the `required` attribute carries the semantic meaning.
- Reduced-motion: all scroll-reveal animations gated on `prefers-reduced-motion: no-preference` (inherited from RevealOnScroll.astro).
- Nav active state: current page nav item gets `aria-current="page"` attribute in addition to `.nav-link--active` class.
- Disabled CTAs (Nieuwsbrief, Boek, NL/EN): `aria-disabled="true"`, `tabindex="-1"`, `title="Binnenkort beschikbaar"` — unchanged from Phase 1 honest-CTA pattern.
