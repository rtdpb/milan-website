# Quick Task 260824-l35 — Koppel custom domain milanvandermeulen.com aan GitHub Pages

## Context

De repo `rtdpb/milan-website` deployt al naar GitHub Pages via `.github/workflows/deploy.yml`,
maar draait onder de subpad-URL `https://rtdpb.github.io/milan-website/`. Het domein
`milanvandermeulen.com` wijst via DNS al naar de GitHub Pages-servers (bewijs: bezoekers krijgen
de GitHub "404 — There isn't a GitHub Pages site here" pagina, niet een DNS/verbindingsfout).

Wat ontbreekt om `milanvandermeulen.com` de site te laten tonen:
1. GitHub weet niet dat deze repo bij dat domein hoort (`pages.cname == null`).
2. De site bouwt onder `base: '/milan-website/'`, dus op de root is er niks.

Interne links gebruiken overal `import.meta.env.BASE_URL` (geverifieerd: geen hardgecodeerde
`/milan-website/` in `src/`), dus het weghalen van `base` is veilig — alle links verschuiven mee
naar de root.

## Tasks

### Task 1 — Config + CNAME voor root custom domain
**Files:** `astro.config.mjs`, `public/CNAME`
**Action:**
- `astro.config.mjs`: `site` → `https://milanvandermeulen.com`; verwijder `base: '/milan-website/'`;
  werk de bijbehorende comments bij (submap-uitleg is niet meer van toepassing).
- Maak `public/CNAME` met exact één regel: `milanvandermeulen.com` (Astro kopieert `public/` naar
  de root van `dist/`, zodat GitHub Pages de domeinkoppeling bij élke deploy behoudt).
**Verify:** `npm run build` slaagt; `dist/CNAME` bevat `milanvandermeulen.com`; gebouwde HTML
verwijst naar root-paden (`/...`) i.p.v. `/milan-website/...`.
**Done:** Build groen, CNAME in dist, geen `/milan-website/` meer in output.
**Commit:** `feat(deploy): serve site on milanvandermeulen.com root (drop base path + add CNAME)`

### Task 2 — Custom domain registreren bij GitHub Pages
**Action:** `gh api -X PUT repos/rtdpb/milan-website/pages -f cname=milanvandermeulen.com`
(via de ingelogde `rtdpb` gh-CLI). Zet daarna HTTPS-enforcement aan zodra het certificaat klaar is.
**Verify:** `gh api repos/rtdpb/milan-website/pages` toont `"cname": "milanvandermeulen.com"`.
**Done:** Custom domain staat geregistreerd aan repo-kant.
**Note:** Geen aparte commit (API-actie, geen bestandswijziging).

### Task 3 — Live deploy + verificatie
**Action:** Push `master` naar `origin` → de `deploy.yml`-workflow bouwt en publiceert automatisch.
Volg de run met `gh run watch`. Controleer daarna dat `https://milanvandermeulen.com` de site
toont (of, kort na eerste koppeling, dat GitHub het SSL-certificaat aan het uitgeven is).
**Verify:** Workflow slaagt; `curl -I https://milanvandermeulen.com` geeft uiteindelijk 200
(certificaat-uitgifte kan 10–30 min duren).
**Done:** Workflow groen; site bereikbaar op het custom domain.

## DNS-fallback (buiten de code, alleen indien nodig)
Als de site na deploy toch niet laadt: controleer bij de registrar dat de apex `milanvandermeulen.com`
deze 4 GitHub-Pages A-records heeft: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`,
`185.199.111.153` (+ optioneel `www` als CNAME naar `rtdpb.github.io`).
