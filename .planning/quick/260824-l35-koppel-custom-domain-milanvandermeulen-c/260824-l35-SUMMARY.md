# Summary — Koppel custom domain milanvandermeulen.com aan GitHub Pages

**Result:** ✅ Site is live op **https://milanvandermeulen.com** (HTTP 200 + HTTPS 200, juiste pagina).

## Wat er gebeurde

Het domein `milanvandermeulen.com` wees via DNS al naar de GitHub Pages-servers (bezoekers kregen
de GitHub-404, niet een DNS-fout). Er ontbraken twee dingen aan GitHub-kant, en die zijn nu geregeld.

### Task 1 — Config + CNAME (commit `cebe8f7`)
- `astro.config.mjs`: `site` → `https://milanvandermeulen.com`; `base: '/milan-website/'` verwijderd
  (root-deploy). Comments bijgewerkt.
- `public/CNAME` toegevoegd (`milanvandermeulen.com`, schone LF, geen BOM) → domeinbinding blijft
  behouden bij élke workflow-deploy.
- `npm run build` groen (16 pagina's). Geverifieerd: **0** `/milan-website/`-referenties in `dist/`,
  canonical + sitemap gebruiken het custom domain, `dist/CNAME` correct.
- Veilig omdat alle interne links `import.meta.env.BASE_URL` gebruiken (geen hardcoded subpad in `src/`).

### Task 2 — Custom domain geregistreerd bij GitHub Pages
- `gh api -X PUT repos/rtdpb/milan-website/pages -f cname=milanvandermeulen.com`
- Read-back bevestigt `"cname": "milanvandermeulen.com"`.

### Task 3 — Live deploy + verificatie
- `git push origin master` → deploy-workflow run `32731354779` groen (build + deploy).
- `curl` bevestigt HTTP 200 én HTTPS 200 op het custom domain; `<title>` klopt.

## Openstaand / follow-up
- **HTTPS-enforce (auto-redirect http→https):** nog niet ingeschakeld — GitHub meldde
  `"certificate does not exist yet"` (cert wordt intern nog afgerond, ~10–30 min). HTTPS zelf werkt
  al voor bezoekers. Later aanzetten via Pages-settings of:
  `gh api -X PUT repos/rtdpb/milan-website/pages -F https_enforced=true`.
- **Analytics-plan** verwees naar `.nl` als toekomstig domein; het echte domein is `.com`. Zodra
  Plausible geactiveerd wordt, `TODO_PLAUSIBLE_DOMAIN` = `milanvandermeulen.com` gebruiken.
- **DNS-fallback** (alleen indien ooit nodig): apex A-records `185.199.108/109/110/111.153`.
